# Fit Extended

> 本项目是 [joshuakto/fit](https://github.com/joshuakto/fit) 的改版分支，基于官方 1.5.0（`0c9630d`）。原插件名 Fit，本分支名为 **Fit Extended**，插件 id `fit-extended`，与原版可并存安装、配置互不影响。许可证沿用 [MIT](LICENSE)。

Fit 是一个通过 GitHub 在多个设备之间同步 Obsidian 库的极简插件。本分支在其双向同步基础上补齐三块能力：单向同步、冲突副本清理、增量与限流治理。

## 相对上游的功能差异

### 单向同步

双向同步会把冲突副本写入 `_fit/` 等待人工合并；有些场景你不需要合并，只想让一端服从另一端。本分支提供两个单向命令，各带**两步独立选项**（每次操作时选择，不写入全局设置）：

- **单向上传**：只把本地内容写入远端，绝不把远端内容写回本地。
- **单向拉取**：只把远端内容写入本地，绝不上传本地内容。

第一步决定同名差异文件如何处理（用来源端覆盖 / 只补新增不覆盖）；第二步决定目标端独有文件是否删除（保留 / 删除）。四个选项的典型用途：

| 第一步 | 第二步 | 用途 |
|---|---|---|
| 覆盖 | 保留 | 日常备份：本地为准，远端多余文件不动 |
| 覆盖 | 删除 | 完全镜像：远端与本地完全一致 |
| 只增 | 保留 | 只补新文件，绝不覆盖远端已有内容 |
| 只增 | 删除 | 只删不覆盖：清理远端多余文件，同时不改动任何同名文件 |

上传/拉取执行前弹出完整路径预览（新增/覆盖/删除分组计数，删除组默认展开），确认后再次校验两端状态——预览之后另一端有变化则中止并提示重新准备，不按过期清单覆盖。`.gitignore`、`.gitattributes` 等隐藏路径永不写入或删除。

### 冲突副本清理

- 双向同步时可当场选择：仅同步保留副本 / 同步后清理本次副本 / 清理全部副本。
- 独立的「清理 _fit/ 冲突副本」命令，可选仅上次同步产生或全部。
- 清理前显示文件、大小与原路径对应关系；确认后只删 `_fit/` 内普通文件，原路径正文永不触碰，删除不向远端传播，逐项报告成功与失败。

### 增量与限流治理

- 单向操作以同步基线（`localSha` / `lastFetchedRemoteSha`）判定增量：只有真正变化的文件参与预览与传输，未变更文件不读取内容。
- 首次使用无基线时，明示确认后**零上传采纳基线**：只读取两端当前状态并记录，不上传、不删除任何文件；之后即可正常增量。
- GitHub REST API 对内容生成请求有二级限流（≤80 次/分钟、≤500 次/小时，见[官方文档](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)）。本分支的 blob 创建改为串行限速（约 80/分钟），收到 403 限流时自动按 60/120/240 秒退避重试；限流与认证错误区分提示。首次全量上传 1000+ 文件约需 13–15 分钟，之后每次只传改动文件。

### 界面汉化

设置页、命令面板、对话框、通知与错误提示全量中文化。来自 GitHub API 的原始错误文本（如 `Bad credentials`）保留英文原样，中文说明附后。日志（debug.log）保持英文，便于对照上游排查。

## 安装

### BRAT（推荐）

1. 安装 [BRAT](https://github.com/TfTHacker/obsidian42-brat)。
2. 命令面板 → BRAT: Add a beta plugin for testing。
3. 输入本仓库地址，确认即可。

### 手动

把 release 资产中的 `main.js`、`manifest.json`、`styles.css` 三个文件复制到 `你的库/.obsidian/plugins/fit-extended/`，重启 Obsidian 并启用。

> 若同一库中装有原版 Fit，两者数据各自独立（`data.json` 位于各自插件目录），凭据不互通，需要在各自设置页分别填写。
