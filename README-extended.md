# Fit Extended

> 本项目是 [joshuakto/fit](https://github.com/joshuakto/fit) 的改版分支，基于官方 1.5.0（`0c9630d`）。原插件名 Fit，本分支名为 **Fit Extended**，插件 id `fit-extended`，与原版可并存安装、配置互不影响。许可证沿用 [MIT](LICENSE)。

Fit 是一个通过 GitHub 在多个设备之间同步 Obsidian 库的极简插件。本分支在上游双向同步的基础上，提供**六类文件处理规则 + 统一人工审阅**。

## 六类文件处理规则

所有入口都作用于**整个知识库**，不提供目录或单文件入口。每条规则都先「检查 → 生成计划 → 审阅 → 执行」，确认前不改动任何文件、不发布提交。

| 规则 | 行为 |
|---|---|
| 仅补充缺失文件 | 来源有、目标没有才写入。目标已有同名文件**绝不覆盖**，目标独有文件保留。包含目标曾主动删除的文件（会补回）。 |
| 单向更新 | 按上次共同状态判断双方改动：仅来源修改才更新目标；仅目标修改则保留；双方结果相同则不动；双方都改且不同则报冲突。目标主动删除而来源未改则保持删除；来源也改则报删改冲突。不传播来源的删除。 |
| 单向覆盖 | 来源存在的文件一律以来源内容为准（即使来源未变、目标变了也覆盖）；保留目标独有文件。 |
| 单向镜像 | 使目标与来源在**实际参与同步的范围**内一致，包括删除目标独有文件。被忽略的对象、Git 元数据、插件运行状态与范围外文件不删。 |
| 双向合并（不传播删除） | 交换新增与修改；一端缺失、另一端仍有则补回（允许文件复活）。改名按路径处理：新增新路径，旧路径保留或补回。双方都没有的文件不从历史恢复。 |
| 双向同步（传播删除） | 基于共同状态交换新增、修改与删除。首次无共同状态时不猜测删除；删改冲突交你决策。 |

单向四类规则在入口处选择方向（本地 → 远端 / 远端 → 本地）；双向两类不设方向。

## 人工审阅（默认流程）

默认「一键同步」固定为**双向同步、传播删除 → 先审阅再执行**。

- 计划按「上传到远端 / 写入本地 / 删除远端 / 删除本地」分组列出路径与计数。
- 支持逐项勾选、全选、全部取消。**全选不会替未决冲突选边**。
- 依赖组联动：同一路径的多个操作要么一起执行、要么一起放弃。
- 未勾选、冲突未决、失败或结果待确认的项目**不视为已同步**，不会推进共同状态。
- 执行前重新校验仓库/分支身份、远端分支头、本地相关路径与忽略规则；任何一项变化则整体拒绝并提示重新检查，不按过期计划覆盖或删除。
- 取消或关闭弹窗不做任何后台动作；没有「暂停/恢复」按钮或锁定状态。

冲突**直接交你决策**：展示双方是否存在及内容事实，选择「采用本地 / 采用远端 / 手工编辑结果」。
- 双向规则下，手工结果写入**两端**（最终双方都等于你确认的内容）；单向规则只写目标端，不反向改写来源端。
- 手工内容可以为空（空文件是合法状态），确认后经同一执行流程写入。
- **二进制文件不提供文本编辑**，只给版本选择（本地 / 远端），并显示类型与大小。

## 首次使用与共同状态

- 「检查」只读取两端状态与必要内容，**不写文件、不发布提交**。
- 首次扫描时，双方同名且内容一致的文件会在执行后确认为「已同步」；内容不同**不会**被当成已同步，而是按规则处理（补缺跳过、覆盖/镜像按来源、更新与双向规则交你决策）。
- 内容一致性用同一口径的内容摘要判断；本地缓存与 Git blob SHA 算法不同，二者从不互相比较或拷贝。
- 从未确认过的路径保持「未知」，不会被推断成「此前不存在」，因此不会把一次部分执行当成另一端删除的依据。

## 忽略规则与同步范围

- **单一规则来源**：只编辑当前仓库共享的 `.gitignore`。本机排除（`.git/info/exclude`）若能读到就按 Git 原生语义参与匹配，界面中**只读展示**；不可访问时如实标注「不可访问」，不用空内容冒充已读。
- **个人全局忽略规则（`core.excludesFile`）当前未读取、未验证**：插件运行环境通常读不到知识库之外的该文件，设置页会如实显示「未配置」，不代表它已参与匹配。
- 展示文件是否被忽略以及对应的规则来源。
- 遵守 Git 原生语义：被忽略的未跟踪文件不参与同步；**已跟踪文件不因新增忽略规则而自动停止跟踪**——这类文件会明确提示，需你自行在 Git 中处理，插件不会替你取消跟踪。
- 共享规则文件本身（`.gitignore`、`.gitattributes`）**会随同步共享**，这是忽略规则在多设备间保持一致的前提；隐藏文件因此经 adapter 单独枚举进快照。
- Git 元数据（`.git/`）、私有排除（`.git/info/exclude`）、Obsidian 设置目录（`.obsidian/` 等）与插件保留区（`_fit/`）不参与内容同步；镜像不会删除它们。
- 若忽略规则读取不完整（例如某目录规则读取失败），本次**不生成计划**并提示，不按残缺规则执行。

## 触发方式

- 默认手动触发检查与计划生成。
- 设置项「打开知识库时自动检查变化」**默认关闭**。开启后，打开知识库时检查一次并保留待审计划，可用命令「审阅待同步计划」直接打开审阅；**不会自动执行同步**。关闭不影响手动同步。
- **没有定时同步**，也没有「是否启用整个仓库同步」的总开关。

## 冲突副本清理（历史兼容）

- 清理是**独立命令**，只用于处理历史上已存在的 `_fit/` 副本。**当前同步流程不会自动生成新的冲突副本**（冲突改为在审阅中由你直接决策），因此这里不提供任何"备份/副本"能力。
- 可选「仅上次同步产生」或「全部」；清理前显示副本与原路径的大小/时间对照。
- 只删除你勾选的 `_fit/` 副本，原路径正文永不删除，删除不向远端传播，逐项报告成功与失败。

## 网络与限流

- 内容创建请求按 GitHub 二级限流约束**真实限速**（约 80 次/分钟，惰性队列，限制发起间隔与在途数量）。
- 收到限流响应时按 `retry-after` 退避重试；限流与认证错误分开提示。
- 远端发布绑定审阅时的分支头（`createCommitOnBranch` + `expectedHeadOid`）：头已变化则整体失败、不写入；**不静默降级为无条件更新**。

## 限制

- **首次建分支未实现（不区分场景）**：空仓库（尚无任何分支）与"已有仓库中创建缺失分支"都尚未实现，会明确返回「不适用」并提示先用 Git 或 GitHub 初始化分支；不会退化为无条件更新或强制推送。
- 仅支持 GitHub。
- 版本历史与回退请使用 Git 工具。
- 手工决策直接写入你确认的最终内容，不提供逐行合并编辑器。

## 安装

### BRAT（推荐）

1. 安装 [BRAT](https://github.com/TfTHacker/obsidian42-brat)。
2. 命令面板 → BRAT: Add a beta plugin for testing。
3. 输入本仓库地址，确认即可。

### 手动

把 release 资产中的 `main.js`、`manifest.json`、`styles.css` 三个文件复制到 `你的库/.obsidian/plugins/fit-extended/`，重启 Obsidian 并启用。

> 若同一库中装有原版 Fit，两者数据各自独立（`data.json` 位于各自插件目录），凭据不互通，需要在各自设置页分别填写。

## 开发

```shell
git clone https://github.com/zuelwyw/fit.git
cd fit && npm install
npm run typecheck    # 类型检查
npm test             # 单元与集成测试
npm run lint -- .    # 代码规范
npm run build        # 产出 main.js（生产构建带空白/语法压缩，保留标识名）
```

开发模式（`npm run dev`）不压缩、带内联 sourcemap；生产构建的 banner 与许可证保留，标识名不压缩以便对照堆栈排错。
